# v0.3 ACPy → frozen ACIR

This increment is intentionally limited to compile-time elaboration. It does
not define a Provider ABI, simulator implementation, Verilog lowering, or JIT
cache.

The v0.3 frontend emits a separate `ac.contract_epoch = "0.3"` artifact and
uses `!ac.queue_v03<T, #ac.queue_contract<...>>`; v0.2 `!ac.queue<T>` artifacts
and public behavior remain unchanged.

## Main-chain contract

| ACPy | frozen ACIR | frozen shape |
| --- | --- | --- |
| `ac.source(T)` | `ac.v03.source` | no input, one Queue result |
| `ac.compute(q, helper)` | `ac.compute` | one Queue in/out and one pure `ac.var.*` region |
| `ac.route(q, by=F, outputs=N)` | `ac.v03.route` | one input and `N` same-payload results |
| `ac.issue(lanes, ...)` | `ac.v03.issue` | named variadic enqueue/wakeup/recheck groups and per-lane issued results |
| `ac.engine(lanes, ...)` | `ac.v03.engine` | equal per-lane issued/completed groups |
| `ac.reorder(completions, ...)` | `ac.v03.reorder` | variadic completions and one ordered retirement Queue |
| `ac.sink(q)` | `ac.v03.sink` | one consuming input |

`issue.width` is the global maximum number of issues per epoch; it is not the
number of engine ports. `reorder.width` is encoded both as a static parameter
and as the retirement Queue rate. `route.by` and `reorder.by` lower to typed,
stable `#ac.field` paths. An issue graph with wakeups must also provide typed
`dependency_key`, `dependency_ready`, and `wakeup_key` descriptors; their key
leaf types must match and the ready field must be `i1`. Engine latency is
selected by a typed `latency_by` field, with separate static `inflight`,
`initiation_interval`, and `kind` parameters.

Python `ac.queue.deferred(T)` and `.bind(q)` only resolve declaration order.
They are unified into the producer Queue identity before frozen ACIR emission,
so no deferred opcode or Python object survives in the artifact.

Repeated consuming uses of one Queue are ACPy broadcast sugar. After deferred
aliases resolve, `SemanticBuilder.freeze()` inserts one strict atomic
`ac.v03.fork` with one result per consuming position, then rebuilds lexical
scope ports from the normalized graph. Read-only `ac.observe` uses do not
participate. Frozen semantic JSON and ACIR therefore retain the native
single-consumer rule and explicit fork representation; v0.2 behavior is
unchanged.

The executable four-lane examples are:

- `tests/python_frontend/fixtures/acpy_v03/davincioo/core.py`: one four-lane
  engine contract;
- `examples/v03/davincioo_dual_cluster.py`: a four-lane issue queue feeding
  separate two-lane integer and vector engine contracts.
